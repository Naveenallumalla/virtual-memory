Why It Matters

Memory Management in Modern Systems

Page replacement is a core OS mechanism used in every major operating system.

🐧

Linux Kernel

Uses a variant of the Clock algorithm (approximation of LRU) via the Active/Inactive page lists in its VM subsystem.

🪟

Windows NT

Implements a Working Set model with LRU-based trimming to manage the physical pages assigned per process.

📱

Mobile / Embedded

Android uses LRU-ordered process lists for the Low Memory Killer to decide which apps to evict from RAM.

☁️

Cloud & Hypervisors

VMware ESXi uses balloon driver + LRU page reclamation to share physical memory across virtual machines.

About Simulator Suite

A production-grade educational tool for understanding virtual memory management.

📋 FIFO — First In First Out

The simplest page replacement policy. Pages are evicted in the order they were loaded. Implemented using a queue.


Pros: Simple, low overhead.

Cons: Suffers from Bélády's Anomaly — more frames can cause more faults.


Real-world use: Simple buffer management, network packet queues.

🕐 LRU — Least Recently Used

Evicts the page that has not been referenced for the longest time. Exploits temporal locality of reference.


Pros: Good performance in practice. No Bélády's Anomaly.

Cons: Requires timestamp tracking; costly in hardware.


Real-world use: Linux kernel page cache, CPU TLB replacement, database buffer pools.

⭐ Optimal (Bélády's Algorithm)

Evicts the page that will not be used for the longest time in the future. Produces the theoretical minimum page faults.


Pros: Minimum possible page faults — the gold standard benchmark.

Cons: Requires future knowledge; not implementable in real systems.


Real-world use: Benchmark for evaluating other algorithms.
